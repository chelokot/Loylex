## Residual risk and rollback

The release RPM is a prebuilt upstream artifact rather than an independently reproducible
local build. The checksum prevents substitution after this review, but it cannot prove that
the upstream build environment was uncompromised. Upstream CI also uses floating action and
tool-version references, so every future PM3 release requires a fresh review. Podman and
podman-compose are version-locked separately and are not changed as a side effect of a PM3
update.

To roll back, restore the last reviewed `versions.env` and the corresponding committed
deployment files, then run the explicit host installer again. The installer changes only
the reviewed stack package pin and preserves the named application volumes; application
container rollback remains handled by the PM3 supervisor's inactive-slot/rollback path.
