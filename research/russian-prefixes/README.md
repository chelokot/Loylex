# Сколько букв различает русское корневое семейство?

Исследование от 27 октября 2026. Это воспроизводимый эксперимент на конечных словарях, **не полный и безошибочный список всех современных русских слов**. Алгоритм различения точен относительно переданных ему слов и меток; выделение лингвистических семейств приближённое.

## Результат

- Основной словник: **95 893 написания**, **96 495 пар (написание, семейство)**, **14 302 группы модели**.
- Минимальное различающее начало: **5,45 буквы** в среднем среди разрешимых исходных записей, медиана 5; 90-й процентиль 7.
- После развёртки известных парадигм: **1 778 766 написаний**, 1 788 207 пар; среднее **5,72 буквы** среди разрешимых записей.
- Начало из 7 букв различает 89,29% исходных пар и 87,71% пар словоформ. Здесь знаменатель включает и неразрешимые случаи.
- `красный / красная / красные → красн` (5 букв); `мрачность / мрачный / мрачнеть → мрач` (4 буквы).

Готовый отчёт: `artifacts/russian-word-signatures.pdf` (8 страниц). Обзор: `artifacts/overview.png`. Локальный `artifacts/explorer.html` содержит поиск по всем исходным записям и их группам; сеть не нужна. Полные CSV генерируются в `results/`.

## Что именно считается

Для написания `w` и семейства `f` ищется минимальная длина `k ≥ 1`, при которой **все** словарные написания, начинающиеся с `w[:k]`, имеют единственную метку `f`. Члены того же семейства не конкурируют друг с другом. Результат вычисляется для **каждой пары**, а не для произвольно выбранного представителя группы.

Если слово является началом слова другого семейства, букв может не хватить: `needs_end_marker=True` означает, что знание о завершении полного слова решит проблему. Если полное написание имеет разные семейства, не поможет и конец слова: нужен контекст либо исправление разметки. Таких случаев программа не притворяется разрешившей.

Поле `competitor` содержит написание другой **метки модели**, ещё допустимое на предыдущем шаге. Для неразрешимой записи конкурент начинается со всего слова. При `k=1` допускается отсутствие конкурента, когда словарь состоит из одного семейства.

Ё приравнена к е; ударения сняты. Дефис участвует в сравнении, но не считается буквой. Позиции морфем и `prefix_characters` измеряются в символах, остальные поля длины — в буквах.

## Модель семейств и её ограничения

1. RuMorphs-Lemmas v0.2 задаёт границы и типы морфем. Из 96 036 входных строк 21 отклонена из-за некорректного написания, несходящегося разбора или отсутствия корня. Повторы и ё/е схлопываются. В релизе отсутствуют некоторые обычные слова, включая `стол` и `красный`.
2. Добавлены ровно две явно обоснованные записи: `красный → красн/ый` из `tikhonovsource.txt` и `мрачность → мрач/н/ость` (корень подтверждён Russian-Derinet и Кузнецовой). Это не скрытая ручная подгонка всего словника: обе добавки записаны в аудите, исходные файлы сохранены.
3. Для основного расчёта выбирается **первый корень**. У многокоренного слова это условность: лесовоз одновременно связан с лесом и возить, и «имеет общий корень» не задаёт естественного непересекающегося разбиения. Сравнительная модель `surface_roots` сохраняет полный упорядоченный набор корней.
4. Словарь Кузнецовой предоставляет омонимические индексы и чередования. Прямая привязка принимается, когда написание корня согласуется с современным морфемным разбором. Так красн- не склеивается с крас- только из-за исторической связи. Метки `K:` — канонические IDs источника; они **могут быть этимологическими**, например `мрак/мрач` имеют глубинный ID `мер³`.
5. При отсутствии прямой привязки используется единственный возможный ID варианта. Для неоднозначного варианта допускается привязка по гнёздам Тихонова только при единственном совместимом ID. Остаток получает метку `R:написание`: это **неразрешённая техническая группа**, а не доказательство, что все её слова однокоренные или что она отличается от всех K-групп. Точное число этих разборов — в `results/summary.json → audit.mapped_assignment`.
6. Известные разборы pymorphy3 объединяют словоизменительные варианты через нормальные формы, присутствующие в исходном наборе. Если написание допускает несколько таких нормальных форм, сохраняются все соответствующие метки. Никакой догадки о неизвестных формах не добавляется.
7. Развёртка строится для 78 288 словарных нормальных форм. Для остальных записей полнота парадигмы не гарантируется. Поэтому набор форм большой, но не исчерпывающий.

Это снимает часть проблем чередований, омонимов и словоизменения, **не решает автоматически всю семантику русского языка**. Средние полезны как свойства конкретной модели. Число 14 302 нельзя объявлять числом корней русского языка. Даже конкурент может быть следствием неправильной технической метки. Частотность употребления и человеческая вероятность угадывания из контекста не измерялись.

## Сравнительные расчёты

- `lemma_families`: основная модель после нормализации известных форм.
- `mapped_roots`: та же модель до нормализации.
- `first_root`: буквальное написание первого корня, без разрешения омонимии и чередований.
- `surface_roots`: полный набор написаний корней, без разрешения омонимии и чередований.
- `tikhonov_nests`: пересечение оцифрованных гнёзд со словарными написаниями. Гнёзда перекрываются, в том числе из-за составных слов; они не объявляются непересекающейся истиной.
- `derinet_broad`: вся доступная большая база DeriNet.RU после фильтра заглавных написаний. Исходные 337 632 строки сохраняются в закреплённом архиве; 113 919 строк с заглавными исключены из расчёта, повторные пары схлопнуты. Ошибки, имена и ложные связи всё равно остаются. Это проверка чувствительности, а не более достоверная оценка.
- `individual_words`: каждое различное написание — отдельная группа, без схлопывания корней.
- `root_signatures`: отдельная задача, когда читателю **уже указана граница корня**. Варианты корня сохраняют те же семейства; омонимичные варианты могут не различаться даже целиком.
- `inflected_forms`: все полученные формы и исходные записи, с сохранением омонимии.

Сравниваются также распознавание справа налево, положение порога относительно корня, размер словаря на фиксированных 2 000 целях, длина слова и перегруженность начал. Изменение среднего по формам нельзя полностью приписывать новым конкурентам: богатые парадигмы меняют веса.

## Повторение

Из корня репозитория, Python 3.12+:

```sh
python research/russian-prefixes/fetch_data.py
python research/russian-prefixes/analyze.py
python -m venv data/russian-prefix-research/venv
data/russian-prefix-research/venv/bin/pip install --only-binary=:all: --require-hashes -r research/russian-prefixes/requirements-inflections.txt
data/russian-prefix-research/venv/bin/python research/russian-prefixes/inflections.py
python research/russian-prefixes/root_signatures.py
python research/russian-prefixes/extra_metrics.py
python research/russian-prefixes/family_table.py
python -m unittest discover -s research/russian-prefixes -p test_analyze.py -v
```

Для графического отчёта нужен Matplotlib 3.11.1 (в исходном окружении уже установлен) и NumPy 2.5.2. Затем:

```sh
python research/russian-prefixes/report.py
```

Основные вычисления используют только стандартную библиотеку Python; анализ форм вынесен в изолированное окружение с закреплёнными колёсами и SHA-256. `fetch_data.py` скачивает только инертные данные, проверяет закреплённые суммы и не исполняет содержимое файлов.

Дерево хранит максимум два различных семейства и свидетелей в узле: этого достаточно, чтобы точно проверить уникальность и найти конкурента. Для большого набора форм применяется сортировка: максимальный общий префикс с другим семейством достигается на ближайшем отличающемся семействе слева или справа. Это позволяет не держать два больших объектных дерева в памяти. Оба алгоритма проверяются друг против друга и против полного перебора на случайных словарях.

`family_summary.csv.gz` содержит отдельную строку на каждое семейство с полным списком членов, вариантами корней, статистиками и набором различающих начал.

В исходных файлах CSV хранятся все корни и морфемы, их позиции, длина слова, минимальный сегмент, его длина, свидетель и флаг конца слова. В CSV словоформ морфемный разбор не выдумывается: записаны форма, семейство, длины, сегмент и свидетель. Источник формы — породившая её словарная лемма с тем же ID; обратные связи по каждой парадигме отдельно не экспортируются.
